# 官网对话桥接原型

**这是可加载的 Chrome / Edge Manifest V3 扩展原型，不是已验证支持七家官网的正式产品。** 不调用付费模型 API，不读取 Cookie、密码或 Token。用户在原浏览器的官网标签页登录；扩展填写输入框、点击一次发送按钮，再同步新增助手回复的可见文字。使用哪个账号、模型和套餐由官网决定。

0.1.1 修复：根据 2026-10-12 的 DeepSeek 实际页面修正无标签发送图标、加载/停止图标与助手正文选择器；支持官网的禁用按钮样式。绑定检查增加超时和错误提示。官网两轮人工式浏览器发送成功，扩展到官网的端到端验收仍未完成。

## 安装与启动

1. 在自己平时登录 AI 官网的 **同一个 Chrome / Edge 浏览器配置文件** 中打开 `chrome://extensions` 或 `edge://extensions`。
2. 开启“开发者模式”，点击“加载已解压的扩展程序”，选择本 README 所在的 `ai-browser-bridge` 文件夹（里面应直接包含 manifest.json）。不需要安装 Node，不需要 API Key。
3. 在工具栏扩展菜单中点“开发练习册 · 官网对话桥接原型”。这会打开独立工作台标签页：左侧是课程网页，右侧是我们自己的聊天界面。收起右侧会恢复课程宽度；窄屏上下排列。
4. 选择服务 → “打开官网登录”。在官网自己登录，选择模型，打开一段空白新对话。保持官网标签页打开，不要同时在里面发送其他消息。
5. 回工作台 → “授权并查找标签页”，仅授予所选服务域名权限 → 明确选择官网标签页 → “绑定并检查”。授权和登录是两件不同的事。
6. 若状态显示输入/发送匹配成功，先发送 `请只回复：桥接测试成功。`。到官网核对收到的消息，再回工作台查看真实回复是否逐段更新。
7. 测长回答可发送 `请分五段解释 HTML、CSS 和 JavaScript 的分工。`。检查官网文字与工作台是否一致，并测试第二轮追问。这两条验证会使用官网当前账号额度。

初次安装后的官网标签页不必刷新，绑定时才注入桥接脚本。更新扩展后应在扩展管理页重新加载，并刷新工作台和官网标签页，避免旧脚本仍运行。

## 校准与故障处理

在“适配诊断 / 校准”中可以填写四个 CSS 选择器，随后重新绑定。输入框与发送按钮必须各匹配唯一可见元素；每条助手回复应匹配一个完整回复容器，排除用户消息与历史导航。停止按钮只在生成时可见。诊断数字是匹配元素个数，不是账号状态。

- 未找到输入框：先检查官网登录、验证码和对话页面；不会自动登录或解决验证码。
- 官网草稿非空：先自己保存或清空，扩展不会覆盖。
- 已点击发送但无回复：用“查看官网”核对额度、报错、页面结构。不要直接重试，防止官网实际上已经收到。
- 默认选择器失效：需要现场校准；原型不会点击任意图标或调用未公开接口作为替代。
- 官方生成仍在继续但文字暂时不变：继续等待；原型不会仅凭静默宣布完成。后台标签页可能被浏览器节流。
- 关闭/刷新官网会解除绑定，不自动重发；刷新工作台丢失内存中的聊天记录。
- “停止同步”只停止观察，不点击官网的停止生成按钮，也不保证节省官网额度。

## 数据与权限

`tabs` 用于列出供用户选择的官网标签页，`scripting` 用于按需注入隔离脚本。官网域名权限在用户点击时请求。没有全站通配授权，没有后台抓取历史，没有分析上报，没有模型网络请求。学习课程在单独 iframe 中显示；代码预览仍由原学习网站的隔离规则控制。

聊天内容只在当前工作台内存中保存，可手动导出 JSON；不把学习进度当作聊天状态，也不会自动完成课时。回复作为纯文字显示，不执行返回的 HTML/Markdown 脚本。为防串话，一个官网标签页同一时刻只允许一条桥接请求。绑定令牌防止其他工作台改变校准后误发。

课程嵌入扩展工作台后，浏览器的存储分区可能与直接打开网站时不同；已有学习记录若没有显示，请从原网页导出，再用课程原有的可撤销导入功能迁入，不要清空原记录。

当前不支持附件、语音、工具结果、官网全部历史导入、历史恢复、云同步和自动新建对话。富文本发送使用浏览器编辑命令；某些官网会拒绝合成事件，需实际验证。回复识别要求新增完整消息节点，虚拟列表复用或多块回复可能读不到/不完整。没有去除官网 CSP、代理登录或绕过服务限制。

## 验证

需要 Node、Playwright 与本机 Edge：

```powershell
node projects/web/ai-browser-bridge/test_bridge.cjs
node projects/web/ai-browser-bridge/test_timeout.cjs
node scripts/check_site.cjs
# 启动仓库静态服务器后运行
node scripts/test_site.cjs
node scripts/test_workbench.cjs
```

桥接测试将扩展复制到 `.qa/bridge/`，仅在测试副本预授权官网域名，然后在独立临时 Edge 配置中加载真正的 MV3 扩展。官网 URL 被本地夹具拦截，验证显式绑定、逐段文字、旧消息排除、草稿保护、纯文本渲染及布局。**它不证明默认选择器或真实会员登录可用。** 测试不会访问个人浏览器配置和凭据。

参考：[Chrome 隔离内容脚本](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、[扩展消息传递](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)。
