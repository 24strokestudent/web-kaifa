## 打开与继承

直接双击本目录 `index.html`，不需要安装依赖或联网。CSS 与 JS 已内嵌，单独复制这个 HTML 即可展示。`tokens.css` 是同一套设计变量的独立导出；集成到正式项目时可以提取内嵌样式并导入它，避免维护两份变量。

也可以在仓库根目录执行 `python -m http.server 8743`，访问 `http://localhost:8743/projects/web/ai-workbook-reference/`。

本稿是交互与视觉参考，不是完整课程迁移。包含 Web / Go 各三个示例，选择、编辑和自查保存在当前页面内存中；刷新前请下载代码与笔记。未改动教材、正式学习进度或根目录网站。

## 审核结论与优先级

| 优先级 | 原稿观察 | 优化方向 |
| --- | --- | --- |
| P0 | `renderAI` 明确只生成提示词，不调用模型；用户期望已扩展为站内对话 | 先确定 AI 连接架构，再实现真实聊天，不能用选择模型或官网登录冒充接通 |
| P1 | `renderLesson` 和 `renderAI` 分属不同页面，提问需要离开课程 | 课程旁常驻、可折叠的对话面板；任务和代码上下文可见、可选 |
| P1 | AI 区域集中多个字段、说明与模板，首轮操作负担较大 | 一个问题输入框，按需要补充代码、报错和尝试；先要线索，再深入 |
| P1 | 学习与工具入口较多，主操作容易被解释文字稀释 | 以当前任务为中心；任务、代码、验收、AI 方法四个标签分层呈现 |
| P1 | 用户希望学习 AI 开发，而不只是复制提示模板 | 显式教授需求澄清、拆任务、增量实现、证据排错、验证复盘 |
| P2 | 原稿绿色主题与大量面板偏资料站 | 暖纸色与陶土色、文档式排版、低装饰工具栏，形成安静的学习工作台 |

原稿应保留的能力：`isReady` 的验收和小测规则；代码 `sandbox="allow-scripts"` 隔离；草稿不自动执行；localStorage 失败提示与异常原记录保留；导入、清空撤销；零基础与有经验者分别适配。参考稿不替代这些已实现能力。

这里没有把美观问题伪装成安全漏洞；本次属于结构与交互审核，不是对原应用的完整安全审计。

## 设计语言

- 布局：桌面课程目录 224px，中间弹性正文，右侧对话 364px。1150px 以下对话改为覆盖面板，760px 以下目录折叠。
- 色彩：暖白 `#faf9f5`，次级纸色 `#f2f0e9`，炭灰 `#302e2b`，辅助文字 `#706c65`，陶土色 `#9b4c34`。强调色只用于选中、提示、少量操作。
- 字体：标题用宋体类衬线，正文用本机中文无衬线，代码用等宽。没有外部字体加载依赖。
- 信息层级：一个明确的课题、一项当前任务、一条主操作；解释放在次级文字与折叠区中。
- 组件：7px 普通圆角、14px 输入框圆角、1px 分隔线；不采用渐变、玻璃效果、大面积阴影或装饰性统计数字。
- 动效：日常切换即时完成；流式演示可停止，尊重减少动态效果设置。焦点轮廓始终可见。
- 文案：具体说明“做什么、怎么验证”；不虚构模型输出、登录成功、学习完成或用户数据。

## AI 产品应该怎样工作

推荐路径：选择服务 → 登录本站 → 选择可用模型 → 勾选本次上下文 → 在本站窗口提问 → 流式接收 → 手动检查改动 → 运行验证 → 自己记录学习结果。

“登录本站”和“获得模型使用权限”是两个不同步骤。正式版由后端配置服务凭证与用户配额，登录后前端读取用户实际可用的模型。模型列表从服务端返回，不把参考稿中的服务名称误当成具体模型 ID。

如果要求使用用户现有的第三方官网会话，需要另行评估官方授权方式或桌面容器方案；这不属于普通静态网页能可靠提供的通用功能。不要尝试靠 iframe 或抓取 Cookie 把官网会员能力变成 API 权限。

### 窗口行为

1. 未连接：显示所选服务与未连接状态，可整理与复制提问。
2. 已认证但服务不可用：显示原因、重新连接入口，保留草稿。
3. 等待首段内容：显示等待状态；禁止重复提交；可取消。
4. 输出中：逐段追加；用户上翻时不强制滚到底部，显示“有新内容”；停止保留已接收内容。
5. 完成：提供复制、追问和“放入草稿”操作；代码必须先看差异、再明确应用，不能自动执行。
6. 超时或断开：保留问题与部分输出；提示重试。重试应有请求标识，避免重复计费或重复插入消息。
7. 切换课程或模型：明确当前对话的归属；跨课上下文需用户主动选择，不能悄悄混入。

参考稿实现了第 1 项和固定说明文字的流式排版预览；其余是正式版要求。演示不生成模型回复，不声称网络 streaming 已实现。

### 建议实现契约（尚未实现）

前端组件可拆为 CourseRail、LessonWorkspace、CodeSandbox、AcceptancePanel、AssistantPanel、ProviderPicker、ConnectionDialog。课程内容使用现有 assets/data，不把六个参考示例当作正式课程替换源。

后端使用独立 Go 模块，提供本站认证、会话存储、模型目录、配额、模型适配器和流式转发。凭证只在服务端保管；会话 Cookie 使用 HttpOnly / Secure，状态修改要有 CSRF 防护。不要把真实 API Key 放在 HTML 或 localStorage。

建议接口：

- `GET /api/session`：当前用户与服务权限。
- `GET /api/models`：服务端允许的模型与可用状态。
- `POST /api/conversations`：创建会话，绑定课程。
- `POST /api/conversations/:id/messages`：提交消息与经用户确认的上下文快照，通过 fetch ReadableStream 读取 SSE。
- `POST /api/requests/:id/cancel`：停止上游生成；前端 AbortController 同时停止读取。

统一事件建议使用 `message_start`、`text_delta`、`message_end`、`error`，附 conversationId、messageId、requestId 和序号。SSE 解析必须处理跨数据块拆分的 UTF-8、多行 data、未完整事件、结束标记和中途错误，不能把网络块当成完整事件。后端需要中断传播、代理禁缓冲和连接超时处理。

真实模型输出视作不可信内容：Markdown 禁止原始 HTML 或使用清洗器；代码进入草稿需确认，继续在不含 allow-same-origin 的 sandbox iframe 内手动运行。用户只发送自己勾选的上下文，不自动上传整个仓库。

### 分期继承

第一期：将本稿的布局和设计变量套入现有课程、草稿、备份和验收逻辑，保留提示词复制能力。

第二期：先接一种服务，完成本站认证、真实 streaming、停止、断线、历史和配额。通过后再扩展多服务。

第三期：加入代码差异审阅、附件和上下文预算；跨设备进度同步要设计冲突与撤销策略。

## 技术依据

- [MDN：frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)：目标网页可以控制哪些父页面能够嵌入它；不能假定第三方官网能直接 iframe。
- [Claude API 认证](https://platform.claude.com/docs/en/manage-claude/authentication)：API 使用明确的服务凭证。
- [Claude 流式消息](https://platform.claude.com/docs/en/build-with-claude/streaming)：模型事件需要增量处理。
- [OpenAI 流式响应](https://developers.openai.com/api/docs/guides/streaming-responses)：正式 streaming 需要从 API 接收事件，前端打字动画不等同于真实流式调用。
