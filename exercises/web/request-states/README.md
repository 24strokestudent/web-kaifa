# 用真实请求验证四种界面状态

这是可运行的基础演示，包含加载、成功、空结果与失败，以及 HTTP 状态和数组形状检查。字段校验、专门的重试入口、请求取消和并行请求处理留作练习。

对应网站：`#/exercise/web-request`。前置知识：async/await、try/catch、DOM。

## 启动

从仓库根目录进入独立练习目录，启动本地 HTTP 服务：

```powershell
cd exercises/web/request-states
python -m http.server 8751
```

访问 `http://localhost:8751/`。Ctrl+C 停止服务。也可以使用仓库根目录的 8743 服务，访问 `/exercises/web/request-states/`。

**不要直接双击 HTML**：file:// 下的 fetch 受浏览器限制，本练习需要 HTTP。没有 npm 依赖，也没有远程 API。

## 验证起点

| 场景 | 网络证据 | 页面预期 |
| --- | --- | --- |
| 正常数组 | items.json，HTTP 200 | 成功，2 场活动 |
| 空数组 | empty.json，HTTP 200 | 空结果，0 条列表项 |
| 不存在 | missing.json，HTTP 404 | 失败，显示 HTTP 404 |
| 坏 JSON | invalid.json，HTTP 200 | 失败，显示 JSON 解析错误 |

`invalid.json` **故意不是合法 JSON**；不要把它“修好”，否则无法验证解析错误。`missing.json` 故意不存在。浏览器在 Console 显示 404 是该场景的预期，不是所有请求都成功的证据。

在 Network 开启限速，点击加载，观察“正在加载…”和暂时不可用的控件。完成后控件恢复。失败后旧列表要清空，不能把旧成功结果留在页面。断网或停止服务后再加载，应进入失败状态。教学演示使用 `cache: 'no-store'`，每次读取新响应，避免缓存掩盖断网结果；这不是对所有产品的缓存策略建议。

## 独立练习与加练

1. 检查数组中每项的 id 和 title，再渲染；使用错误形状的 JSON 验证。
2. 增加明确的重试按钮，保证一次失败后可以恢复。
3. 加练：用 AbortController 与最新请求标记允许切换场景并取消旧请求。
4. 记录预期、真实状态码、界面结果和自己的解释，回到课程笔记保存。

## 已知限制

起点在加载时锁住场景选择，暂不支持并行请求。只检查顶层数组，没有完整数据字段校验。不写入数据，不提供数据库、认证或真实报名。取消信号需要请求逻辑主动处理，不能把隐藏加载文字当成取消完成。
