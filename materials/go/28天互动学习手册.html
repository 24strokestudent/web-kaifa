01

环境、工具链与程序入口

必学0/4

能独立创建 Go 模块、运行、格式化、构建和排查最基本的环境问题。

第 1 周 · 2h

01Go 安装与 PATH

去 go.dev/dl 安装当前受支持的稳定版，终端执行 go version；Windows 推荐 PowerShell + VS Code Go 扩展。

常见坑 · 装了 Go 但旧终端找不到 go，先重开终端并确认 PATH。

02package main 与 main()

可执行程序必须属于 main 包并包含 func main()；import 是引入包，不是 C++ 的 #include 文本复制。

常见坑 · 同目录不同 .go 文件不能随意声明成不同包。

03go mod init

在项目根目录执行 go mod init example/go-practice；go.mod 说明模块路径与所需 Go 版本。

常见坑 · 不要把 go.mod 当成源代码，更不要每建一个文件都初始化一次模块。

04go run、go build

go run . 直接编译并运行；go build ./... 构建所有包；go run main.go 可能漏掉同包其他源文件。

常见坑 · 项目有多个 .go 文件时优先用 go run .。

05gofmt、go test、go vet

go fmt ./... 自动格式化，go test ./... 运行测试，go vet ./... 做静态检查。

常见坑 · 格式统一是 Go 的常规工程约定，不是选修美化。
★ 这章练什么

在 Windows 新建 go-lab 项目，打印姓名、今天的学习目标，再修改输出并重新运行。

验收标准：截图或文本记录 go version、go run . 的输出；提交包含 go.mod、main.go、README.md 的第一个 commit。

02

基础语法与控制流

必学0/5

利用 C++ 的已有基础快速迁移，不再背诵你已经懂的循环和条件思想。

第 1 周 · 3h

01变量与短声明

var n int = 3、n := 3、const pi = 3.14；:= 仅能在函数内部声明变量。

常见坑 · Go 编译器通常不允许局部变量声明后未使用。

02类型与显式转换

int、int64、float64、bool、string；数值类型不同通常需要显式转换，例如 int64(n)。

常见坑 · 不要假设 Go 自动完成 C++ 风格的数值混用。

03零值

数字是 0、bool 是 false、string 是空串、指针/slice/map/interface 等有 nil 零值。

常见坑 · nil map 可读取但不能直接写入。

04if 与作用域

if err := do(); err != nil { ... } 支持判断前的短语句，变量只在该 if 相关作用域有效。

常见坑 · if 后没有小括号，左大括号必须与条件处于同一行。

05只有 for

for i := 0; i < n; i++、for condition、for { } 三种常见模式；没有 while 关键字。

常见坑 · 不能像 C++ 写 ++i 作为表达式；++ 是语句。

06switch

可省略表达式，case 默认不会自动 fallthrough；适合替代多级 if。

常见坑 · 与 C++ switch 默认穿透行为不同。

07函数、多返回值

func div(a,b int) (int,error) 可以同时返回结果和错误；Go 没有常规函数重载。

常见坑 · 不要忽略返回的 err，也不要用 panic 替代正常错误处理。
★ 这章练什么

写一个命令行成绩统计器：输入若干分数，计算最小值、最大值、平均值，非法分数返回错误。

验收标准：至少测试空输入、正常输入、负数、超过 100 的分数四种情况。
掌握程度：能做到以下事情再勾选
03

slice、map 与字符串

必学0/5

能用 Go 的主要容器代替 vector、unordered_map，避免常见的 nil 和复制陷阱。

第 1 周 · 3h

01数组与 slice

[3]int 是长度属于类型的一部分的数组；[]int 是动态切片，具有 len/cap，底层引用数组。

常见坑 · slice 赋值和切片可能共享底层数据，修改一处影响另一处。

02append 与扩容

s=append(s,x) 返回新的 slice 值，扩容时可能搬迁底层数组。

常见坑 · 不能只调用 append(s,x) 却丢掉返回值。

03make 与 nil

make([]int,0,10)、make(map[string]int) 用来初始化 slice/map；nil slice 可以 append。

常见坑 · nil map 不能赋值，nil slice 与空 slice 序列化 JSON 时可能不同。

04map 读写

m[k]=v；v,ok:=m[k] 判断是否存在；range map 遍历顺序不保证稳定。

常见坑 · 不能把 map 的随机遍历顺序用作分页或稳定输出。

05range 的语义

for i,v := range xs 遍历的是每轮元素值；直接改 v 不会修改 slice 中的原元素。

常见坑 · 更新元素请用 xs[i] = ...。

06string、byte、rune

Go 字符串存 UTF-8 字节序列；len("中") 是 3，[]rune("中") 长度为 1。

常见坑 · 处理中文字符个数不能直接用 len(string)。

07排序与常用库

slices.Sort、sort.Slice、strings、strconv 是常见工具；记住搜索文档而非硬背所有 API。

常见坑 · 不要把字符串字典序误当数值顺序。
★ 这章练什么

单词频率排行：从一行文本提取单词，忽略大小写，输出次数前 3 的单词；同次数按字典序排序。

验收标准：测试重复词、空文本、并列次数，排序结果每次运行一致。
掌握程度：能做到以下事情再勾选
04

struct、方法、指针、接口

必学0/5

无需先学传统 OOP：掌握数据结构、方法、组合以及小接口就能开始开发。

第 1 周 · 3.5h

01struct 组织数据

type Problem struct { ID int64; Title string } 将字段组织在一起，类似 C++ struct。

常见坑 · Go struct 不等于 class；没有类继承和传统构造函数强制机制。

02方法 receiver

func (p Problem) IsSolved() bool 是绑定到命名类型的方法；可以给自定义类型添加行为。

常见坑 · 只有 receiver 参数不同通常不构成重载。

03值接收者与指针接收者

func (p *Problem) MarkSolved() 会修改原对象；值接收者拿到一份副本。

常见坑 · 想改结构体字段但用了值接收者会导致原值没变化。

04指针与 nil

&p 取地址，*p 解引用；Go 有垃圾回收，无需用 new/delete 管理普通对象生命周期。

常见坑 · 不要解引用 nil 指针；不必一见指针就想到 C++ 的手动释放。

05导出规则

跨包访问的标识符首字母大写，如 Problem、Title；小写只在包内可见。

常见坑 · json 编码一般只处理可导出的字段；小写字段即使写了 json tag 也不生效。

06interface 隐式实现

type Store interface { Save(Problem) error }；实现了所需方法的类型即满足接口，无需 implements。

常见坑 · 不要一开始给每个结构体都抽象一个接口；让需求决定接口。

07组合优先

struct 可以嵌入其他字段或类型，用组合复用数据/行为；不要把 C++ 继承层级直接搬到 Go。

常见坑 · 接口表示行为契约，不代表继承树。
★ 这章练什么

实现 Problem{ID,Title,Solved} 与 MarkSolved()；写一个按标题关键字筛选 []Problem 的函数。

验收标准：调用方法后原对象真的改变；输出 JSON 含正确字段；能演示值接收者与指针接收者的区别。
掌握程度：能做到以下事情再勾选
05

error、defer、JSON、I/O

必学0/5

学会后端最常碰到的错误传播和请求 JSON 解析。

第 1 周 · 3h

01error 是值

函数返回 (T,error)，约定 err==nil 表示没有错误；用 if err != nil 尽早返回。

常见坑 · 不要用 panic 处理用户输入不合法等预期情况。

02包装与识别错误

fmt.Errorf("load problem: %w",err) 保留错误链；errors.Is(err,sql.ErrNoRows) 判断类别。

常见坑 · 仅拼接字符串会丢失可识别的错误链。

03defer

defer rows.Close() 表示函数返回时执行清理；常用于文件、响应体与数据库游标。

常见坑 · defer 的执行时机是当前函数返回，不是当前 if 块结束。

04JSON struct tag

`json:"title"` 控制字段名，`omitempty` 可以省略适用的空值字段。

常见坑 · 导出字段、JSON 标签和请求结构需对应；不能只靠标签导出私有字段。

05Encoder/Decoder

json.NewEncoder(w).Encode(value)，json.NewDecoder(r.Body).Decode(&input)；编码错误和写响应顺序都要处理。

常见坑 · 不要在写状态码之前已向响应写入数据，否则状态码可能固定为 200。

06输入尺寸与格式校验

限制请求体字节数，检查类型、长度、必填项，并识别多余 JSON 数据；适时使用 DisallowUnknownFields。

常见坑 · 解析成功不代表业务有效，例如 title 仍可能是空串。
★ 这章练什么

读取题目 JSON，拒绝空标题、过长标题、无法解析的 JSON，返回结构化错误结果。

验收标准：验证字段缺失、未知字段、错误字段类型、过大 Body、额外 JSON 文档。
掌握程度：能做到以下事情再勾选

包管理、测试入门和命令

必学0/4

理解 Go 项目的构成和开发时必须会用的 6 条命令。

第 1 周 · 2h

01包与模块的层次

目录通常是一个 package；module 可包含多个 package，go.mod 声明依赖图与模块路径。

常见坑 · 不要从绝对 Windows 路径 import 本地 Go 文件。

02import 循环依赖

Go 不允许包互相 import 构成环；把共同类型移到合适包或重新划分职责。

常见坑 · 不要为绕开循环依赖而建几十个空目录。

03go mod tidy

整理实际导入依赖；go.sum 保存模块校验信息，应正常提交版本控制。

常见坑 · 不要随意删除 go.sum 来“修复”依赖。

04gofmt 与惯例

Go 项目统一 gofmt，命名偏短、可读，错误及时返回。

常见坑 · 不要机械套用 C++ 复杂命名和宏体系。

05小测试先行

使用 *_test.go、func TestXxx(t *testing.T)，运行 go test ./...；先测纯函数最容易上手。

常见坑 · 测试是否通过不等于需求正确；断言必须对照独立的预期。
★ 这章练什么

把成绩统计器拆成 calc 包和 main 包，为平均值函数写 4 个测试。

验收标准：编译无循环依赖；所有测试通过，并故意修改实现使至少一个测试失败。

Web 基础：一次请求发生了什么

必学0/4

理解浏览器、客户端、服务器、TCP/HTTP、URL 和 JSON 的分工。

第 1～2 周 · 3h

01前端与后端

浏览器负责界面，后端接收请求、执行业务规则、读写数据、生成响应；API 是双方的契约。

常见坑 · 浏览器看到 JSON 不代表“没有后端”，恰好可能是 API 成功返回。

02URL 结构

协议、主机、端口、路径、查询参数；例如 http://localhost:8080/problems?page=2。

常见坑 · Query 参数与 JSON Body 是不同位置，不可混淆。

03HTTP 方法

GET 读取、POST 创建/触发、PATCH 局部修改、PUT 通常整体替换、DELETE 删除；应遵循预期语义。

常见坑 · GET 不应偷偷修改数据；重复提交 POST 的影响要考虑。

04状态码

200 成功、201 创建、204 无内容、400 参数错误、401 未认证、403 无权限、404 不存在、409 冲突、500 服务端异常。

常见坑 · 400 和 500 不可一概混用；401 与 403 有明确区别。

05Header、Body、Content-Type

Content-Type: application/json 声明消息体格式，Authorization 用于携带授权凭据。

常见坑 · 不能靠 URL 参数传密码和长期密钥。

06JSON 数据协议

对象、数组、布尔、数字、null；后端输入输出用稳定字段与约定好的错误结构。

常见坑 · 数字字符串 "2" 与 JSON 数字 2 不是一种类型。
★ 这章练什么

不用框架，先用浏览器和 curl/PowerShell Invoke-RestMethod 查看两个公开测试接口的响应头和 JSON。

验收标准：能说出请求方法、URL、状态码、响应体各自是什么；能解释 404 与 500 的区别。
掌握程度：能做到以下事情再勾选

net/http 与路由处理

必学0/5

只用标准库就能写出真正可访问的 Go HTTP API。

第 1～2 周 · 3.5h

01ServeMux 与 Handler

http.NewServeMux() 注册路由，处理函数签名为 func(http.ResponseWriter,*http.Request)。

常见坑 · ResponseWriter 是输出通道，Request 是输入，不要反着理解。

02路由模式与 PathValue

Go 1.22+ 支持 "GET /problems/{id}"，用 r.PathValue("id") 取路径参数。

常见坑 · GET 方式路由也匹配 HEAD；需要理解协议行为。

03Query 与表单

r.URL.Query().Get("page") 取查询参数；字符串需 strconv.Atoi 转换并检查 err。

常见坑 · 查询参数可能缺失、重复或不是整数。

04Body 解码

通过 json.NewDecoder(r.Body).Decode(&req) 接收 JSON，设置请求大小限制并校验输入。

常见坑 · 只解析不校验容易造成脏数据甚至过大请求。

05写状态码和 JSON

先设置 Header，再 WriteHeader，再写 Body；无特殊情况 Encoder.Encode。

常见坑 · 先 Write 了响应体，再改状态码通常已经无效。

06HTTP 服务器设置

http.Server 可配置 ReadHeaderTimeout、ReadTimeout、WriteTimeout；初学部署也应避免无约束超时。

常见坑 · http.ListenAndServe 的最简示例适合本地学习，公网服务还需要更多保护。

07调用工具

curl -i、curl.exe -i 与 PowerShell Invoke-RestMethod 都能测接口；Windows PowerShell 的 curl 别名可能指向 Invoke-WebRequest。

常见坑 · 不要把 PowerShell curl 别名行为当成标准 curl 的参数规则。
★ 这章练什么

实现 GET /health、GET /hello?name=、GET /add?a=3&b=5。

验收标准：合法参数得到 JSON，缺失或非法数字得到 400；用命令行至少测试各 2 个场景。
掌握程度：能做到以下事情再勾选

REST API、CRUD 与校验

必学0/5

独立设计和实现内存版刷题记录 API，掌握真实业务接口的最小闭环。

第 2 周 · 4h

01资源建模

把 Problem 看作资源：ID、platform、title、difficulty、solved、created_at。

常见坑 · 不要把每个操作都写成 /doAddProblem 这样的随意路径。

02CRUD 端点

GET /problems、GET /problems/{id}、POST /problems、PATCH /problems/{id}、DELETE /problems/{id}。

常见坑 · GET 列表与 GET 单条的响应形状需清楚区分。

03请求 DTO 与领域对象

CreateProblemRequest 不应该由用户指定数据库生成的 ID；响应 DTO 可以屏蔽敏感字段。

常见坑 · 直接绑定数据库模型到请求体容易暴露不该由客户端更改的字段。

04输入验证

标题不为空且长度受限，difficulty 在允许值集合内，ID 是正整数。

常见坑 · 错误值不要悄悄当成默认值，除非 API 明确约定。

05统一错误响应

例如 {"error":{"code":"INVALID_INPUT","message":"title required"}}，便于前端处理。

常见坑 · 错误时不应返回 200，也不要把数据库密码泄漏到客户端。

常见坑 · http.Server 会并发处理请求，裸写全局 map 会引发数据竞争。

database/sql 连接 PostgreSQL

必学0/6

让 Go API 真的读写数据库，而不是用内存假装“后端开发完成”。

第 2 周 · 4.5h

01标准库与驱动

database/sql 提供接口与连接池，PostgreSQL 要安装相应驱动，例如 pgx/v5/stdlib。

常见坑 · database/sql 本身不是数据库驱动。

02sql.Open 与 PingContext

sql.Open 创建 DB handle，不保证马上连接成功；使用 PingContext 验证可访问。

常见坑 · 错误的地址和密码应在启动时尽快反馈。

03QueryRowContext

查询一条记录后 Scan；查询不到行会在 Scan 时得到 sql.ErrNoRows。

常见坑 · 不检查 ErrNoRows 就可能错误返回 500。

04QueryContext 与 rows

遍历 rows.Next()，逐行 Scan；defer rows.Close()，循环后检查 rows.Err()。

常见坑 · 只检查 QueryContext 的 err 还不足以发现遍历过程中的错误。

05ExecContext 与 RETURNING

UPDATE/DELETE 可通过 RowsAffected 判断是否修改了记录；PostgreSQL 的 INSERT ... RETURNING id 可返回新 ID。

常见坑 · 不同数据库对 LastInsertId 的支持不同，Postgres 通常用 RETURNING。

06SQL 参数绑定

PostgreSQL 使用 $1、$2 等占位符，参数单独传入；绝不 fmt.Sprintf 拼接用户值。

常见坑 · 拼接 SQL 可产生注入漏洞，尤其是来自 URL/Body 的内容。

07连接池与超时

*sql.DB 是并发安全的连接池句柄；设置 MaxOpenConns、MaxIdleConns，并给请求设置 context 超时。

常见坑 · 不要在每个请求里重新 sql.Open 一个连接池。
★ 这章练什么

将刷题 API 的内存存储替换为 PostgreSQL；添加两次后重启 Go 服务，记录仍在。

验收标准：所有 CRUD 持久化、非法 ID 返回 400/404，SQL 没有字符串拼接输入；数据库不可用时返回合理服务端错误并记录日志。

认证、鉴权与 Web 安全

项目必学0/5

在理解普通 CRUD 后，再给项目添加用户账号并保护私人数据。

第 4 周 · 4h

01认证 vs 鉴权

认证（Authentication）确认“是谁”；鉴权（Authorization）判断“能操作哪些资源”。

常见坑 · 登录成功不代表可以访问所有用户的数据。

02密码处理

使用成熟密码哈希算法（例如 Argon2id/bcrypt 的可信实现），存哈希不存明文；比较时用库提供的安全方法。

常见坑 · SHA256(password) 或简单加盐哈希不适合存储用户密码。

03Session 与 JWT

Session 通常服务端存状态；JWT 是签名 token，不能因为解码出用户 ID 就信任它，必须校验签名、算法、有效期、签发方等。

常见坑 · 不要将 JWT 理解成天然加密或无需撤销策略。

04Cookie 属性

HttpOnly、Secure、SameSite 帮助降低部分风险；基于 Cookie 的状态改变请求需要考虑 CSRF。

常见坑 · 只设置 HttpOnly 并不能解决所有 XSS/CSRF 问题。

05对象级权限

例如 GET /problems/{id} 必须检查该题目属于当前用户，不只是要求登录。

常见坑 · 这是初学后端非常容易漏掉的越权问题。

06SQL 注入、XSS 与 CORS

SQL 参数绑定；输出到 HTML 时正确转义；CORS 只是浏览器跨源访问策略，不是认证与鉴权。

常见坑 · 开放所有 Origin、把 Token 放 URL 都可能制造问题。

07速率限制和安全边界

对登录、注册等接口控制频率；限制 Body 大小；使用 HTTPS；按最小权限运行和连接数据库。

常见坑 · 本地练习可简化，但公网暴露前要建立基本安全措施。
★ 这章练什么

给刷题记录增加账户，用户 A 登录后不能读取/修改用户 B 的题目。

验收标准：用户密码只存安全哈希；未登录与越权有不同响应；完成至少 2 个越权用例测试。
掌握程度：能做到以下事情再勾选

并发、context 与优雅退出

项目必学0/5

理解 Go 后端的并发运行环境，并让取消、超时、共享数据有明确行为。

第 4 周 · 3.5h

01goroutine

用 go f() 启动并发任务，调度由运行时负责；HTTP server 会并发服务请求。

常见坑 · 创建 goroutine 不等于它可以无限运行或自动处理返回结果。

02channel

用于 goroutine 间通信；理解发送/接收、缓冲、有无发送者时的阻塞。

常见坑 · 不要为了使用高级语法而给每次数据库查询都包一层 channel。

03Mutex 与 RWMutex

保护共享可变内存；并发 map 读写需要同步，数据库连接池本身可并发使用。

常见坑 · 锁的范围太大可能严重拖慢吞吐。

04context

请求上下文传递取消信号/截止时间，数据库与外部 HTTP 调用接受 ctx。

常见坑 · 不要把 context 当作装载所有业务数据的万能 map。

05超时与资源释放

context.WithTimeout 和 defer cancel()；避免请求已取消仍无止境运行。

常见坑 · 忘记 cancel 可能延迟资源回收。

06优雅退出

接收关闭信号后使用 http.Server.Shutdown(ctx)，给正在进行的请求收尾机会。

常见坑 · 直接 os.Exit 可能中断未完成的请求或日志写入。
★ 这章练什么

给 API 加数据库 2 秒超时；模拟慢操作，确认客户端取消可传递；压测并发读取。

验收标准：超时可以结束，服务退出不强制丢弃已有请求；-race 在测试覆盖路径中没有发现竞争。

可直接运行的示例：main.go

代码示例 · go
package main

import (
    "bufio"
    "fmt"
    "os"
)

func calc(a, b int) (int, int) {
    return a + b, a * b
}

func main() {
    in := bufio.NewReader(os.Stdin)
    out := bufio.NewWriter(os.Stdout)
    defer out.Flush()
    var n int
    if _, err := fmt.Fscan(in, &n); err != nil { return }
    sum := 0
    for i := 0; i < n; i++ {
        var x int
        if _, err := fmt.Fscan(in, &x); err != nil { return }
        if x > 0 { sum += x }
    }
    a, b := calc(sum, 2)
    fmt.Fprintln(out, a, b)
}

拆解：&n 把变量地址交给扫描函数，类似 C++ 的引用输入；a, b := calc(...) 接住两个返回值；defer out.Flush() 在 main 返回时刷新缓冲区。err 不是异常，而是函数返回的一部分，Day 5 会系统讲。

可直接运行的示例：main.go

代码示例 · go
package main

import (
    "fmt"
    "sort"
    "strings"
    "unicode/utf8"
)

type Pair struct { Word string; Count int }

func main() {
    text := "Go go Cpp go CPP"
    counts := make(map[string]int)
    for _, word := range strings.Fields(strings.ToLower(text)) {
        counts[word]++
    }
    var list []Pair
    for word, count := range counts {
        list = append(list, Pair{word, count})
    }
    sort.Slice(list, func(i, j int) bool {
        if list[i].Count != list[j].Count { return list[i].Count > list[j].Count }
        return list[i].Word < list[j].Word
    })
    fmt.Println(list) // [{go 3} {cpp 2}]
    fmt.Println(len("中文"), utf8.RuneCountInString("中文")) // 6 2
}

拆解：counts[word]++ 读取不存在的键会得到 int 的零值，因此词频可以直接累加；排序先比较频次、再比较单词，才能在频次相同时稳定输出。sort.Slice 的比较器回答“下标 i 的元素是否排在 j 前面”。

package main

import (
    "encoding/json"
    "fmt"
)

type Problem struct {
    ID     int64  `json:"id"`
    Title  string `json:"title"`
    Solved bool   `json:"solved"`
}

func (p *Problem) MarkSolved() { p.Solved = true }
func (p Problem) IsSolved() bool { return p.Solved }
func (p Problem) WrongChange() { p.Solved = false } // 仅修改副本

func main() {
    p := Problem{ID: 1, Title: "Two Sum"}
    p.MarkSolved()
    p.WrongChange()
    data, err := json.Marshal(p)
    if err != nil { panic(err) }
    fmt.Println(p.IsSolved(), string(data))
}

拆解：p.MarkSolved() 可写成看似对象调用的方法；Go 会按规则取得地址，使指针接收者方法修改原对象；WrongChange 的修改丢失是因为接收者拷贝。这里的 panic 只为展示不可预期的内部错误，不应拿来响应无效用户输入。

知识点与任务的对应关系

  • error 是普通返回值 → func parse(...) (Problem,error)；成功时 err == nil，失败时携带原因，通常立即 return。
  • 错误包装 → fmt.Errorf("decode request: %w", err) 能保留底层错误，errors.Is 可判断已知错误。
  • defer → 函数返回时执行清理，如 defer file.Close() 或 defer rows.Close()；不是离开 if 就立即执行。
  • JSON 与字段标签 → json.Unmarshal 把字节解码到结构体；json.Marshal 生成 JSON；json:"title" 控制字段名。
  • 语法有效 ≠ 业务有效 → { "title": "" } 是合法 JSON，但对新建题目来说无效；需要 strings.TrimSpace 再校验。

可直接运行的示例：main.go

代码示例 · go
package main

import (
    "encoding/json"
    "fmt"
    "io"
    "strings"
)

type CreateProblem struct { Title string `json:"title"` }

func parse(s string) (CreateProblem, error) {
    dec := json.NewDecoder(strings.NewReader(s))
    dec.DisallowUnknownFields()
    var p CreateProblem
    if err := dec.Decode(&p); err != nil { return p, fmt.Errorf("decode: %w", err) }
    if err := dec.Decode(new(any)); err != io.EOF { return p, fmt.Errorf("expected one JSON object") }
    if strings.TrimSpace(p.Title) == "" { return p, fmt.Errorf("title required") }
    return p, nil
}

func main() {
    for _, input := range []string{`{"title":"Two Sum"}`, `{"title":" "}`, `{"title":10}`} {
        p, err := parse(input)
        fmt.Printf("%+v, error=%v\n", p, err)
    }
}

拆解：Decode(&p) 把 JSON 写入目标结构体，所以传的是地址；JSON 字段类型错了会返回错误；业务非法必须另写校验。用 err != io.EOF 判断第二次解码是一种演示写法：真实项目还要区分第二次解码失败与多值输入，以便给出精确响应。

练习与验收

  1. 让输入来自标准输入或文件，解析成功后输出标准化 JSON。

  3. 写 validateTitle 函数，让错误原因既能打印出来又能被调用者处理；额外试验一次 defer 关闭文件。

今天为什么学：从今天起，你写的程序不再是“运行一次结束”，而是长期监听端口，等待客户端通过 HTTP 调用。

知识点与任务的对应关系

  • 客户端—服务器 → 浏览器/curl 发请求，Go 服务接收后选择 Handler，构造状态码、Header、Body 返回。
  • URL 结构 → http://localhost:8080/add?a=1&b=2：8080 是端口，/add 是路径，?a=1&b=2 是查询参数。
  • http.HandlerFunc → 函数签名 func(w http.ResponseWriter, r *http.Request)；r 是输入，w 是输出。
  • ServeMux → 标准库路由器，注册方法与路径，例如 GET /health。Go 1.22 及更高版本支持这种路由模式。
  • 状态码与 Content-Type → 成功常用 200，输入错误用 400，内部故障才使用 500。响应 JSON 时设置 application/json。
  • 类型转换与校验 → Query 参数全部是字符串，调用 strconv.Atoi 转换，失败应立即返回 400。

可直接运行：main.go

代码示例 · go
package main

import (
    "encoding/json"
    "log"
    "net/http"
    "strconv"
)

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json")
        _ = json.NewEncoder(w).Encode(map[string]string{"status": "ok"})
    })
    mux.HandleFunc("GET /hello", func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json")
        _ = json.NewEncoder(w).Encode(map[string]string{"message": "hello Go"})
    })
    mux.HandleFunc("GET /add", func(w http.ResponseWriter, r *http.Request) {
        q := r.URL.Query()
        a, e1 := strconv.Atoi(q.Get("a"))
        b, e2 := strconv.Atoi(q.Get("b"))
        if e1 != nil || e2 != nil || !q.Has("a") || !q.Has("b") {
            http.Error(w, "a and b must be integers", http.StatusBadRequest)
            return
        }
        w.Header().Set("Content-Type", "application/json")
        _ = json.NewEncoder(w).Encode(map[string]int{"sum": a + b})
    })
    log.Println("listening on http://localhost:8080")
    log.Fatal(http.ListenAndServe(":8080", mux))
}

package main

import (
    "encoding/json"
    "net/http"
    "strconv"
    "log"
)

type Problem struct {
    ID int `json:"id"`
    Title string `json:"title"`
}

func main() {
    data := []Problem{{1, "Two Sum"}, {2, "Binary Search"}}
    mux := http.NewServeMux()
    mux.HandleFunc("GET /problems", func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json")
        _ = json.NewEncoder(w).Encode(data)
    })
    mux.HandleFunc("GET /problems/{id}", func(w http.ResponseWriter, r *http.Request) {
        id, err := strconv.Atoi(r.PathValue("id"))
        if err != nil || id <= 0 { http.Error(w, "invalid id", 400); return }
        for _, p := range data {
            if p.ID == id {
                w.Header().Set("Content-Type", "application/json")
                _ = json.NewEncoder(w).Encode(p)
                return
            }
        }
        http.Error(w, "not found", 404)
    })
    log.Fatal(http.ListenAndServe(":8080", mux))
}

            http.Error(w, "expected one JSON object", 400)

        return

    if req.Title == "" { http.Error(w, "title required", 400); return }

核心代码：MemoryStore（可放入独立包）

代码示例 · go
package store

import "sync"

type Problem struct { ID int64; Title string; Solved bool }
type Patch struct { Title *string `json:"title"`; Solved *bool `json:"solved"` }
type MemoryStore struct {
    mu sync.RWMutex
    data map[int64]Problem
}
func New() *MemoryStore { return &MemoryStore{data: make(map[int64]Problem)} }

func (s *MemoryStore) Get(id int64) (Problem, bool) {
    s.mu.RLock()
    defer s.mu.RUnlock()
    p, ok := s.data[id]
    return p, ok
}
func (s *MemoryStore) Patch(id int64, req Patch) (Problem, bool) {
    s.mu.Lock()
    defer s.mu.Unlock()
    p, ok := s.data[id]
    if !ok { return Problem{}, false }
    if req.Title != nil { p.Title = *req.Title }
    if req.Solved != nil { p.Solved = *req.Solved }
    s.data[id] = p
    return p, true
}
func (s *MemoryStore) Delete(id int64) bool {
    s.mu.Lock()
    defer s.mu.Unlock()
    if _, ok := s.data[id]; !ok { return false }
    delete(s.data, id)
    return true
}

拆解：Patch 的指针字段用于区分未提供与提供零值。RLock 是读锁，Lock 是写锁；加锁后配套 defer Unlock，减少错误路径忘记解锁。上面示范的是存储层代码，HTTP 层需自行补 URL 参数、JSON 解码与状态码。

核心片段：从数据库读取列表

以下代码属于你的 repository 层，需要 Day 13 的 db *sql.DB 与你定义的 Problem 类型。它演示正确的多行读取生命周期。

代码示例 · go
func ListProblems(ctx context.Context, db *sql.DB) ([]Problem, error) {
    rows, err := db.QueryContext(ctx, `
        SELECT id, title, platform, difficulty, solved
        FROM problems ORDER BY id`)
    if err != nil { return nil, fmt.Errorf("query problems: %w", err) }
    defer rows.Close()
    result := make([]Problem, 0)
    for rows.Next() {
        var p Problem
        if err := rows.Scan(&p.ID, &p.Title, &p.Platform, &p.Difficulty, &p.Solved); err != nil {
            return nil, fmt.Errorf("scan problem: %w", err)
        }
        result = append(result, p)
    }
    if err := rows.Err(); err != nil { return nil, fmt.Errorf("rows: %w", err) }
    return result, nil
}

  • 测试独立性 → 预期结果应该由需求或人工算出，不要调用同一个被测实现计算 want。

    "context"
    "database/sql"

    "testing"

func TestInsertAndRollback(t *testing.T) {
    dsn := os.Getenv("TEST_DATABASE_URL")
    if dsn == "" { t.Skip("set TEST_DATABASE_URL for integration test") }
    db, err := sql.Open("pgx", dsn)
    if err != nil { t.Fatal(err) }
    defer db.Close()
    ctx := context.Background()
    tx, err := db.BeginTx(ctx, nil)
    if err != nil { t.Fatal(err) }
    defer tx.Rollback()
    var id int64
    err = tx.QueryRowContext(ctx, `INSERT INTO problems
        (title,platform,difficulty) VALUES ($1,$2,$3) RETURNING id`,
        "test-one", "local", "easy").Scan(&id)
    if err != nil { t.Fatal(err) }
    if id <= 0 { t.Fatalf("invalid id: %d", id) }
}

func parsePagination(q url.Values) (page, limit int, err error) {
    page, limit = 1, 20
    if s := q.Get("page"); s != "" {
        page, err = strconv.Atoi(s)
        if err != nil || page < 1 { return 0, 0, fmt.Errorf("invalid page") }
    }
    if s := q.Get("limit"); s != "" {
        limit, err = strconv.Atoi(s)
        if err != nil || limit < 1 || limit > 100 { return 0, 0, fmt.Errorf("invalid limit") }
    }
    if page > 1000000 { return 0, 0, fmt.Errorf("page too large") }
    return page, limit, nil
}

拆解：url.Values 来自 net/url，strconv.Atoi 和 fmt.Errorf 要导入相应包。上面的函数属于一个更大的 Go 包，并非独立程序。OFFSET 适合入门和小数据量；数据量巨大时了解基于游标的 keyset pagination。

知识点与任务的对应关系

  • 认证（Authentication） → 确认请求来自哪个已登录用户；例如用户提交凭据后建立会话。
  • 鉴权（Authorization） → 即使已经登录，也必须判断是否有权限读取、修改或删除某条资源。
  • 用户与资源归属 → users 表存账号，problems.owner_id 关联用户；每个查询都应限定当前用户。
  • 密码存储原则 → 不保存明文或可逆加密的密码，使用专门的密码哈希算法和唯一随机盐。
  • 最小权限 → 认证通过不代表可以访问任意用户 ID；管理员权限是另外设计的问题。
  • 统一错误语义 → 未登录为 401；登录但无权访问可选 403，或在资源层统一返回 404 防止暴露资源是否存在。

  • 注册流程 → 验证邮箱和密码规则 → 对密码做专用哈希 → 保存用户记录；邮箱唯一性要由数据库约束。

代码示例 · go
package main

import (
    "fmt"
    "log"
    "golang.org/x/crypto/bcrypt"
)

func main() {
    password := []byte("strong passphrase 123")
    hash, err := bcrypt.GenerateFromPassword(password, bcrypt.DefaultCost)
    if err != nil { log.Fatal(err) }
    fmt.Println("saved hash:", string(hash))
    err = bcrypt.CompareHashAndPassword(hash, password)
    fmt.Println("correct password:", err == nil)
    err = bcrypt.CompareHashAndPassword(hash, []byte("wrong"))
    fmt.Println("wrong password:", err == nil)
}

拆解：同一密码每次哈希的字符串通常不同，因为包含随机盐；验证不是重新哈希后直接对比文本，而是使用 CompareHashAndPassword。bcrypt 有 72 字节输入长度限制，真实项目要明确处理过长密码；更深入可比较 Argon2id 的适用性。

今天为什么学：后端安全漏洞经常不是“没人登录就进来”，而是“登录 A 后，通过改 URL 中的 ID 读到了 B 的数据”。

知识点与任务的对应关系

  • 可信身份从何而来 → 服务端通过 Session/JWT 的合法性校验得到用户 ID；不能直接信任请求里的 user_id 字段。
  • Session vs JWT → Session 常用随机令牌 + 服务端存储；JWT 是签名令牌，但依旧要验证签名、有效期及适用范围。
  • 授权检查 → 每条查询都带 owner_id 条件，避免先把别人的数据读出来再决定不显示。
  • 对象级鉴权 → 不仅列表要筛选，单条 GET、PATCH、DELETE 也要检查资源归属。
  • 401/403/404 → 无有效会话返回 401；无权限访问现有对象时可 403 或 404，保持策略一致。
  • 退出与过期 → Session 需要有限有效期；退出时使服务端会话失效。仅删除浏览器 Cookie 不能撤销全部服务端凭据。

知识点与任务的对应关系

  • 输入验证 → 字段类型、长度、枚举范围、未知 JSON 字段和过大的 Body 都要有明确规则。

BUILD · 动手

▤本日配套教材 · 知识点 + 实操为什么学 · 原理拆解 · 示例代码 · 练习验收⌄

今天为什么学：Go Web 服务在同一时刻可以接收多个请求。如果共享数据操作不加保护，或者关闭服务时直接杀进程，就可能出现竞态和中断。

知识点与任务的对应关系

  • goroutine → go f() 在新的 goroutine 并发执行，不等于每一个都会独占一个系统线程。
  • channel → goroutine 之间传递数据或同步的一种方式；先了解作用，不要求今天实现复杂 worker pool。
  • sync.Mutex / RWMutex → 保护共享可变内存，尤其是第 11 天的 map；并发读写 map 不安全。
  • context.Context → 随请求传递截止时间和取消信号；数据库调用使用 r.Context() 或其派生 context。
  • 超时 → context.WithTimeout 限制慢查询占用资源，函数返回时调用 cancel()。
  • 优雅退出 → 停止接收新连接，给在途请求留出收尾机会，再关闭数据库连接池。
  • go test -race → 动态检查实际跑到的路径中的数据竞争；检查没报警不等于所有并发问题都不存在。

优雅退出的最小可运行程序：main.go

代码示例 · go
package main

import (
    "context"
    "log"
    "net/http"
    "os/signal"
    "syscall"
    "time"
)

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("ok"))
    })
    srv := &http.Server{Addr: ":8080", Handler: mux, ReadHeaderTimeout: 5 * time.Second}
    ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)
    defer stop()
    go func() {
        if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
            log.Printf("server error: %v", err)
            stop()
        }
    }()
    <-ctx.Done()
    shutdownCtx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()
    if err := srv.Shutdown(shutdownCtx); err != nil { log.Printf("shutdown: %v", err) }
}

拆解：go func(){ ... }() 启动一个 goroutine 运行服务器；主 goroutine 等待系统退出信号；Shutdown 让 HTTP Server 有机会处理在途请求。这个示例使用 syscall 的传统信号常量，适合跨平台理解，实际 Windows/Linux 行为需按环境测试。

练习与验收

  1. 为一次耗时数据库查询加 context.WithTimeout(r.Context(), 2*time.Second)；观察超时如何传递。
  2. 给内存存储写一个并发测试，先故意去掉锁运行 go test -race，再恢复锁并检查。
  3. 运行 API，发出一个持续几秒的请求，再用 Ctrl+C 退出，查看是否有机会完成请求或在期限内取消。

过关标准：能区分“数据竞争”“业务逻辑竞态”“超时取消”三个概念，不再把 goroutine 理解为自动安全。

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-go@v7
        with:
          go-version-file: go.mod
          cache: true
      - name: Check formatting
        run: |
          files=$(gofmt -l .)
          test -z "$files" || { echo "$files"; exit 1; }
      - run: go vet ./...
      - run: go test ./...
      - run: go build ./...

06 / TRANSFER MAP

看得懂 C++，怎么翻译到 Go？

只记 Go 与 C++ 不同的地方。最重要的是 slice/map 语义、大小写导出规则、error 返回值以及指针接收者。

你熟悉的 C++对应 Go一定要注意
#include <bits/stdc++.h>import (...)按包引入；没有万能头文件
int main()func main()可执行代码在 package main
auto x = 3;x := 3短声明只能在函数内部
vector<int> a;a := []int{}切片不是完整的 C++ vector 复制语义
a.push_back(x);a = append(a, x)别丢掉 append 的返回值
unordered_map<string,int>map[string]int写入前 make 初始化
for (auto &x : a)for i := range a修改 a[i]，range 的 value 是副本
pair<int,int>struct 或多返回值Go 函数可以 return x,y
nullptrnil引用类类型的零值
string.size()len(s)len(string) 返回 UTF-8 字节数
class / public / privatestruct + 方法 + 大小写导出没有传统类继承；大写跨包导出
throw / catchreturn value, err普通失败走 error，不靠 panic
new / delete&v / new(T) + GC一般无需手动释放内存
std::mutexsync.Mutex保护共享内存，非数据库连接对象
std::threadgo f()运行时调度，并发先学正确性
std::optional<T>(T, bool) 或 (T,error)依语义返回存在性或错误
std::map 有序遍历map 顺序不保证需要稳定顺序自己取 key 排序
cout / cinfmt / bufioWeb 开发更常用 HTTP Body 与 JSON
没学 OOP 能学 Go 后端吗？能。先理解：struct 组织数据，method 为类型添加行为，interface 表达某种行为契约。Go 不使用传统的 class 继承系统；接口在理解抽象和测试时逐渐学就够了。

package main

import (
    "fmt"
    "strconv"
)

func parseID(s string) (int64, error) {
    id, err := strconv.ParseInt(s, 10, 64)
    if err != nil || id <= 0 {
        return 0, fmt.Errorf("invalid id %q", s)
    }
    return id, nil
}

func main() {
    id, err := parseID("12")
    if err != nil {
        fmt.Println("失败:", err)
        return
    }
    fmt.Println(id)
}
⑤ 直接运行的第一个 HTTP 后端保存为 main.go：GET /health 和 GET /add?a=3&b=5。
package main

import (
    "encoding/json"
    "log"
    "net/http"
    "strconv"
    "time"
)

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json")
        _ = json.NewEncoder(w).Encode(map[string]string{"status": "ok"})
    })
    mux.HandleFunc("GET /add", func(w http.ResponseWriter, r *http.Request) {
        q := r.URL.Query()
        a, errA := strconv.Atoi(q.Get("a"))
        b, errB := strconv.Atoi(q.Get("b"))
        if errA != nil || errB != nil {
            http.Error(w, "a and b must be integers", http.StatusBadRequest)
            return
        }
        w.Header().Set("Content-Type", "application/json")
        _ = json.NewEncoder(w).Encode(map[string]int{"result": a + b})
    })
    srv := &http.Server{Addr: ":8080", Handler: mux, ReadHeaderTimeout: 5 * time.Second}
    log.Fatal(srv.ListenAndServe())
}

type CreateProblemRequest struct {
    Title    string `json:"title"`
    Platform string `json:"platform"`
}

// handler 内：先限制体积，再解码。
r.Body = http.MaxBytesReader(w, r.Body, 1<<20)
var req CreateProblemRequest
dec := json.NewDecoder(r.Body)
dec.DisallowUnknownFields()
if err := dec.Decode(&req); err != nil {
    http.Error(w, "invalid JSON", http.StatusBadRequest)
    return
}
var extra any
if err := dec.Decode(&extra); err != io.EOF {
    http.Error(w, "only one JSON value is allowed", http.StatusBadRequest)
    return
}
if strings.TrimSpace(req.Title) == "" {
    http.Error(w, "title is required", http.StatusBadRequest)
    return
}

func TestHealth(t *testing.T) {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("Content-Type", "application/json")
        fmt.Fprint(w, `{"status":"ok"}`)
    })
    req := httptest.NewRequest(http.MethodGet, "/health", nil)
    rec := httptest.NewRecorder()
    mux.ServeHTTP(rec, req)
    if rec.Code != http.StatusOK {
        t.Fatalf("status = %d, want 200", rec.Code)
    }
    if !strings.Contains(rec.Body.String(), `"status":"ok"`) {
        t.Fatalf("body = %q", rec.Body.String())
    }
}

✕ AI 一次写完整项目

✓ 让 AI 解释错误、审阅你的实现；每天至少自己完整写一次核心功能。

✕ 只做能成功的测试

✓ 故意测非法输入、缺失资源、越权、断连，才知道系统边界。

✕ 目录层数越多越“企业级”

✓ 按实际职责划分；初学项目 main+handler+store 即可起步。

✕ 只背语法不做项目

适合让 AI 做

术语小词典

API

应用程序接口；这里通常指前端与服务器沟通的 HTTP 约定。

CRUD

Create/Read/Update/Delete，增删改查。

HTTP

请求—响应协议，方法、路径、状态码、Header、Body 组成一次交互。

HTTPS

HTTP over TLS；网络传输加密并支持服务器身份验证。

REST

一种资源导向的架构风格；关键是明确资源、方法与响应语义。

JSON

文本数据交换格式；Go 主要用 encoding/json。

Handler

接收 HTTP 请求并写响应的处理函数/对象。

Middleware

在最终 Handler 前后执行共同逻辑，如日志、认证等。

DTO

传输数据对象；定义客户端允许提交、接收的字段。

Repository

隔离数据库操作的代码职责，不必一开始就建复杂框架。

Module

以 go.mod 定义依赖和模块路径的项目单元。

Package

Go 源文件的组织与命名空间；目录通常对应一个包。

Slice

动态切片，指向底层数组的一段视图。

Interface

方法集合构成的行为契约；Go 隐式实现。

Receiver

声明方法时绑定到类型的接收者。

Pointer receiver

对接收者指针操作，通常用于修改值或避免复制大对象。

Zero value

变量未显式初始化时对应类型的默认零值。

error

用于返回可预期失败信息的内建接口类型。

defer

安排在当前函数返回时执行的语句。

Context

取消、截止时间和请求范围信号的传递机制。

Goroutine

由 Go 运行时调度的轻量并发执行单元。

Mutex

互斥锁，用来保护共享可变状态。

Race condition

多种执行时序导致结果变化；数据竞争是其中一种具体问题。

SQL injection

把不可信数据拼接进 SQL 文本，令其改变查询含义的漏洞。

Migration

版本化数据库结构变更，使环境可一致重建。

Transaction

保证一组数据库操作以一致方式提交或回滚。

Index

辅助数据库加速查找/排序的结构，存在成本。

Authentication

认证：确认用户身份。

Authorization

鉴权：确认用户对资源/动作的权限。

JWT

签名令牌格式；不能将它误认为加密或自动安全。

CORS

浏览器跨源请求访问控制；不是后端授权机制。

CI

持续集成；每次提交自动运行检查和测试。

Docker

打包与运行容器的工具；和数据库持久化/部署策略分开理解。
